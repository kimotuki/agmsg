# test-gen-r-yamaguchi

`$ARGUMENTS` で指定されたファイルに対し、このリポジトリ(agmsg)の既存テスト形式に合わせた bats テストを作成し、すべて通るまで直す。

## 前提

- テストランナーは `bats`(`bats --version` で確認。無ければ `brew install bats-core`)。
- テストは `tests/*.bats`。共通ヘルパーは `tests/test_helper.bash`。
- 対象が bash スクリプト以外(`.js` など)の場合は、既存の同種テストを探して形式を合わせる。見つからなければユーザーに確認する。

## 手順

### 1. 対象の特定と読み込み
- `$ARGUMENTS` が空、またはファイルが存在しない場合は、その旨を伝えて止まる。推測で別ファイルを選ばない。
- 対象ファイルを全文読む。引数、終了コード、出力メッセージ、副作用(DB・設定ファイルの変更)、`source` している lib を把握する。

### 2. 既存テストの形式を調べる
- `grep -rln "<対象のファイル名>" tests/` で、すでに対象を扱うテストを探す。あればそのファイルに追記する。無ければ最も近い既存の `tests/test_*.bats`(同じ領域のもの)を選ぶか、新規ファイルを作る。
- 選んだ `.bats` と `tests/test_helper.bash` を読み、次を踏襲する。
  - `load test_helper` と `setup()` / `teardown()`(`setup_test_env` / `teardown_test_env`)
  - スクリプトは `bash "$SCRIPTS/<name>.sh"` で呼ぶ(隔離した一時ディレクトリにコピーされたものが使われる)
  - 実行は `run`、判定は `[ "$status" -eq N ]` と `[[ "$output" =~ "..." ]]`
  - テスト名は `"<スクリプト名>: <振る舞い>"` の形式。`# --- <name>.sh ---` の見出しコメントで区切る
  - `HOME` は `test_helper` が隔離済み。実環境(`~`、`/tmp` 直書き)に触れない
- 既存のコメント密度・命名・インデントに合わせる。

### 3. テストケースを設計する
最低限、次を網羅する。該当しない項目は省く。

**正常系**
- 代表的な引数での期待どおりの出力と終了コード 0
- オプション・任意引数(省略時の既定値、指定時の挙動)
- 副作用がある場合は、その結果(DB の内容、作成されたファイル)

**異常系**
- 必須引数の欠落(`${1:?...}` による非 0 終了)
- 存在しない対象(team、agent、ファイルなど)
- 不正な値(数値でない limit、空文字列)
- クォート `'`、`%`、`_`、`\`、改行、日本語などの特殊文字(SQL や sed を使うスクリプトでは必須)
- 空の状態(DB 未初期化、データなし)

各テストは 1 つの振る舞いだけを検証し、「一致すべきもの」と「一致してはいけないもの」の両方を assert する。終了コードだけで済ませない。

### 4. テストを書く
- 手順 2 で選んだファイルに追記する(既存テストは変更・削除しない)。
- 対象スクリプトの仕様を変えない。テストが失敗した場合に直すのはまずテスト側。

### 5. 実行して通るまで直す
1. `bats tests/<対象の.bats>` を実行する。
2. 失敗したら、出力から原因を切り分ける。
   - **テストの誤り**(期待値の間違い、ヘルパーの使い方、クォートのミス): テストを直す。
   - **対象スクリプトのバグ**: 勝手に直さない。失敗するテストの内容と原因をユーザーに報告し、修正してよいか確認する。確認が取れるまで、そのテストは残したまま(スキップしない)報告に含める。
3. 修正したら再実行する。全件通るまで繰り返す。同じ失敗が 3 回続いたら止めて、状況をユーザーに報告する。
4. 通ったら、関係する既存テストが壊れていないことを確認するため、同じ `.bats` 全体を実行する。リポジトリ全体(`bats tests/`)は時間がかかるため、ユーザーが求めたときだけ実行する。

### 6. 報告
簡潔に次を伝える。
- 追加したテストの数と、ファイル名
- 正常系と異常系のそれぞれの内訳
- 実行結果(件数と、通った/通らなかった)
- 対象スクリプトのバグを見つけた場合は、その内容と、未対応であること

## 注意
- コミット・push はしない。変更は作業ツリーに残す。
- 検証していないものを「通った」と報告しない。`bats` を実行できなかった場合は、その旨を明記する。
